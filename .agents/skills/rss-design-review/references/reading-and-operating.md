# 読書面と操作面の判断基準

ImpeccableのRead / Operate / layout / typeset / polishをRSSの既存UIへ適応した改変版。元の自動実行手順は含めない。出典は [skill-sources.md](../../../../docs/design/skill-sources.md)。

## 読む・探す・管理する

本文では文字幅、行間、見出し、画像の扱いと読み進める位置を優先する。一覧では比較しやすいタイトル、未読・保存状態、現在の対象と件数を優先する。サイドバーでは購読先と整理の階層を優先する。この3つに同じ強さの装飾や操作密度を適用しない。

何が選ばれているか、何件あるか、どの条件で絞り込んでいるかを追えるようにする。フィード・タグ・コレクションが積集合を作る場合、単独の選択名だけで状態を説明しない。表示方式とおすすめの連続読書のような別機能を同じ入口にまとめても、状態と意味は分けて示す。

操作を削除して見た目を整えたことにしない。移動先が見つかり、操作前後の状態が分かり、元の作業に戻れることを確認する。常時操作は既存規則のリーダー11操作以内、副次操作は近いdisclosure、まれな管理は設定や既存メニューへ置く。

## 密度と形

余白は意味の区切りに使う。コンパクトな購読・一覧の面で余白を増やす場合、最初のフィード、記事、本文がどれだけ下へ押されるかを実寸で比較する。短いラベルが有効な操作を選び、すべてのアイコンに広いテキストボタンを追加しない。

密集した操作の角丸、高さ、文字、ボーダーを共通部品とトークンでそろえる。fine pointerの32pxとcoarse pointerの44pxの規則を守る。見た目を小さくするためにヒット領域を縮めない。200pxの一覧など実際のリサイズ下限と、モバイルのタッチ条件は別々に確認する。

最小幅でも折り返しや適切なdisclosureを使い、重要な操作をクリップや横スクロールの奥に置かない。単一のスクリーンショットから、内部ペイン幅や中間幅でも収まると推測しない。

## 文字と静けさ

管理UIは既存の`text-control`以上を操作ラベルに、`text-meta`を副次情報に使う。本文と記事タイトルの階層は別に保つ。新しいフォントや色を増やす前に、既存のサイズ・ウェイト・意味色で解決する。

背景・罫線・影で同じ階層を何重にも囲わない。アクセントは現在位置と主操作、状態色は未読・保存・エラーの意味に使い、混同しない。動きは状態を説明する場合に限定し、reduced motionでも作業の意味が残るようにする。

## 判断の証拠

対象の画面と状態を決め、PC・狭いモバイル・中間幅、明暗テーマ、長い日本語ラベル・URL、空・読み込み・エラー・選択・無効状態から変更に関係するものを確認する。文字拡大・reflowは対応する実ブラウザーで評価する。

ナビ→一覧→本文→戻る、検索とフィルター解除、読書モードの開始と終了、設定の検索と復帰を関連範囲で操作する。全体UIを評価する場合、切り出したtoolbarだけでは本文や購読先が押し出される影響を判断できない。

報告は「観測した問題→利用者への影響→変更→同条件の検証」をつなげる。ソース上の予測、合成画面の描画、実アカウントでの動作は別の証拠として記録する。
