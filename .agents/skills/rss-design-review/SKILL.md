# RSSの読書・操作デザイン

画面の主目的、現在の対象と状態、利用者が次に行う操作を先に決める。装飾より、購読先を選ぶ→記事を探す→読む→必要な管理を行う流れの分かりやすさを評価する。

まずリポジトリの指示と [.claude/rules/design-system.md](../../../.claude/rules/design-system.md) を読む。`docs/design/reading-workspace.md` がある場合は最新の採用方針も読む。既存の決定と今回の依頼を優先し、未知のブランド要件や利用者の好みを作らない。

UIの設計・見直しでは [読書面と操作面の判断基準](references/reading-and-operating.md) を参照する。意味のある変更案を短く説明してから、許可された範囲で実装する。

- RSSのコンパクトな3ペイン、既存のセマンティックトークンとinline SVGを基準にする。新しいヒーロー・カード・広い操作帯を自動的に持ち込まない。
- 読書面の高頻度操作と、表示・設定・管理を区別する。機能を隠すときは入口、現在状態、復帰方法を確認する。
- PCとモバイルで実際に描画した画面と関連操作を確認する。比較には同じ合成データ、フォント、テーマ、幅、状態を使い、exact commitまたはpatch digestを記録する。
- 画像・実操作・ソースからの推論を区別する。描画できない場合は具体的な制約と未検証項目を残し、外観を検証済みとしない。

必要な改善と未解決の判断を、重要度と証拠付きで報告する。検証した範囲が依頼の受け入れ条件を満たしたら終了し、際限なく磨くことを目的にしない。

これはImpeccableのRead/Operate等をRSS用に改変した、文章だけの判断支援。上流の自動検出・エンジン・コマンドは提供しない。出典・変更点・ライセンスは [skill-sources.md](../../../docs/design/skill-sources.md)。
