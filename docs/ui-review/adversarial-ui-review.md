# 敵対的 UI/UX レビュー (2026-10-09)

「とっちらかってきた」というオーナーの違和感を、あえて辛口で検証したレビュー。

- 環境: `pnpm dev` + dev 認証バイパス + `/api/test/seed` の合成データ (3 フィード / 60 記事)。Chromium (Playwright) でデスクトップ 1440x900、モバイル 390x844 (DPR 2, touch) を撮影。
- 対象: フィード一覧、記事一覧、リーダー、各種メニュー、設定、MCP 同意 / 連携設定、空・オフライン状態。
- スクリーンショット: PR の Cloud Agent artifacts (`screenshots/ui-review/{before,after}/{desktop,mobile}-*.png`)。リポジトリには画像を入れていない (約 12MB のため)。
- 基準: `.claude/rules/design-system.md` (注: 依頼文の `docs/design-system.md` は存在せず、正本はこのファイル)。
- 限界: コントラスト比は実測ではなく、design-system 記載のトークン値 (AA 以上) を前提にした目視確認。スクリーンリーダーでの読み上げ確認はしていない。dev 環境のレート制限トースト (リクエスト過多) と Next dev バッジは本番 UI ではないので指摘から除外した。

## 総評

機能は増え続けたが、**「常時見せる操作」と「ときどき使う操作」の区別が UI にない**。どの面でも、同じ重みのアイコンが一列に並び、重要度の差が視覚に出ていない。その結果、1 画面あたりの操作点数が多すぎ、小さい画面ではそれが折り返し・横スクロール・隠れ操作として表面化している。

### 1. リーダーヘッダー

デスクトップでも 24px の無ラベルアイコンが一列で、似た形 (フィルター / 全体フィルター) の区別は tooltip 頼み。「全体フィルター」は一覧ヘッダーにも同じ機能があり重複している。モバイルでは 44px 目標のために 3 行へ折り返し、アイコンの意味と重要度が読めない。

### 2. 記事一覧ヘッダー

`overflow-x-auto` の 1 本の帯に表示切替 6 + フィルター 11 が入っていた。最も使われる未読 / ブックマークの切替が、既定幅のペインでは視界の外にある。横スクロールできることを示す手がかりもない。

### 3. おすすめカード

3 件を出すだけなのに、1 件ごとに 3 行の補助 UI があり、合計で一覧ペインの半分近くを使う。主役 (記事) より補助 (理由・調整・興味なし) の方が目立つ。

### 4–5. サイドバーとピルの大きさ

大きさのルールが場所ごとに違う (44 / 32 / 24 / 20 / 10px)。タッチ環境の 44px は守るべきだが、細かいポインター環境まで同じにすると密度が崩れる。

### 6. MCP ページ

同意画面は認可の判断を求める画面なのに、許可ボタンが 5 段落の注意書きの下にあり、モバイルでは初回表示に出ない。

### 7–8. 常設バーと設定

常設バーは機能として必要だが、主操作より弱くあるべき。設定のプレビューは操作と同時に見えて初めて意味があるので、小さい画面では短くする。

### 9–10. 未対応の理由

- 9: 見出しの予約高は `reader-title.spec.ts` などでレイアウト安定を保証している意図的な仕様。変更は本文の読み始め位置に波及するため、別途検証が必要。
- 10: 変更面が広く、他の指摘と同じ PR に混ぜると検証が追えなくなる。

## 実施した対応の要約

| 指摘 | 変更                                                                                                                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 常時表示は 11 操作に絞り、画像保存 / オートモード / 読み上げ速度・音量 / フィルター / 全体フィルター / 印刷 / フォーカスを「その他の操作」(`aria-expanded`) に移動。使用中の状態はドットで示す |
| 2    | 表示切替の行とフィルターの行を分離。使用頻度の低い 5 項目 (ダイジェスト / 日付 / 読了時間 / カテゴリ / 全体キーワード) は「詳細フィルター」に集約し、適用中は自動で表示                        |
| 3    | 補助 UI を 1 行に集約 (理由テキスト + 「理由」+「興味なし」)。重複する説明段落を削除。アクセシブル名は維持                                                                                     |
| 4    | 既定で閉じる disclosure に変更し、件数を表示。更新ボタンに押せる大きさを確保。エラー時は自動で開く                                                                                             |
| 5    | ポインターが細かい環境では 32px、タッチでは 40x44px。11px 直書きを `text-meta` へ                                                                                                              |
| 6    | 共通の `renderMcpPage` に、トークン値を写したスタイル (ライト / ダーク) を持たせ、許可ボタンを注意書きの前に配置。主 / 副 / 危険のボタン階層を追加                                             |
| 7    | 未押下のスイッチを枠なしにし、細かいポインターでは高さ 32px。ブランド文字を `text-meta` (11px) に                                                                                              |
| 8    | モバイルではプレビューを最大 7rem に制限 (タブ数の削減は未対応)                                                                                                                                |

## 検証

- `pnpm run check` / `pnpm run typecheck` / `pnpm run test:unit` (SQLite に FTS5 がない環境の `article-search-index.test.ts` 28 件を除く全件)。
- `pnpm run test:e2e:scoped` (Chromium fixture)。日付フィルターを使う `scoped-recommendations.spec.ts` は、日付が「詳細フィルター」内に移動したため、先に開く手順を 1 行追加した。skip / retry の追加はない。
