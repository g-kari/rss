# 通信失敗後の読書状態を再同期する

既読・ブックマーク・後で読む・いいね・メモ・タグなどの同期が失敗した後、別の編集をしなくても既存のオンライン復帰・タブ復帰・バックグラウンド遷移で再試行できます。失敗した差分を復元した際にも、同期待ちの内部状態を保持する修正です。

- 再試行は既存の `/api/read-state` を使用します。失敗を理由に自動ポーリングを開始しません
- タブ復帰時は未送信の変更を先に保存し、同時の古い GET 応答で変更を上書きしないようにします
- 保存中に追加編集があれば、先行リクエストが成功しても同期待ちの表示を維持します
- 失敗後の終了時も既存の beacon / overflow バックアップ経路を利用します

## 検証

単体テストは失敗後のオンライン復帰・即時同期・非表示/表示への遷移、終了時の overflow、保存中の追加編集、重複復帰イベントとポーリングなしを固定します。Chromium の合成 origin では実際の hook と API wrapper を使い、失敗した POST の同じ差分が再送されることと既存の終了時バックアップを確認します。

本番の個人データを編集する検証は行いません。ブラウザー/OS が終了時の送信を受け付けること、localStorage の容量や利用可否は保証できません。認証・保存形式・同期先・データマイグレーション・インフラは変更しません。
