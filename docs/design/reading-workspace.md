# 読書 UI の判断基準と検証

## 採用した方向

実描画で比較した広い操作ラベル案では、常用操作が分かりやすくなる代わりに本文と購読フィードが下へ押し出された。コンパクトな #1469 を基準とする。旧 #1468 候補 [7b6d8da](https://github.com/g-kari/rss/commit/7b6d8dac03b463d750466752bdda9ce284ce39c6) は比較用の履歴として残し、一括採用しない。[同条件の比較 run](https://github.com/g-kari/rss/actions/runs/37972420036) の画像は実 App と合成データ、同じ production フォントで描画したもの。比較の描画24ケースは成功したが、この run 全体は設定入口のテストセレクターで失敗したため、最終検証成功の証拠ではない。

## 利用者の仕事と情報の階層

1. 購読先・グループ・タグ・コレクションを選ぶ。左は場所の選択と管理、中央の見出しで現在位置を確認できる。
2. 未読を探し、検索・絞り込み・並び替えで読む記事を決める。中央は一覧とおすすめが主役。表示方法は一覧の操作、読書方式は「読み方」にまとめる。
3. 本文を読み、必要なら保存・共有・読書補助を使う。本文は主役、常用操作は近くに置き、低頻度の操作は既存の「その他の操作」に残す。
4. 管理・通知・AI・表示設定を調整する。設定は既存の目的別カテゴリとローカル検索を使う。管理操作を常用の読書面に増殖させない。

ビジュアル表示は見た目の選好、ドパガキモードはスコープ内のおすすめを順番に読む機能であり、状態は独立して保持する。同じ「読み方」入口で役割を説明する。NSFW 表示の状態・解除は「読書・表示」設定に置き、既存の長押し解除も保つ。

## 見た目・入力の規則

- 密集した一覧操作は角丸四角で統一。短い「未読」「絞り込み」のラベルだけを加え、広い新操作帯を作らない。
- 件数は0でも表示。フィード・グループ・タグとコレクションを同時に絞り込んだ場合は、その積集合を見出しに表示する。長い現在位置の名前は省略できるが title と accessible name に全文を保つ。表示切替は200pxの最小一覧幅でも必要なら折り返し、横スクロールの奥へ隠さない。
- 読書設定・要約・翻訳の高さをそろえる。fine pointer は32px、coarse pointer は44pxの既存方針を保つ。サイズ統一のためにタッチ領域を縮めない。
- button / summary の Space はそのコントロールが所有する。body の Space / Shift+Space は記事を一度だけスクロールし、フォーカス読書の trusted overlay を優先する。
- メニューの Escape と読書モード終了時は、閉じた領域の内部ではなく可視の入口へフォーカスを戻す。表示・既読・購読・保存・検索・動画再生の状態を保つ。
- motion の軽量化・prefers-reduced-motion、明暗テーマ、既存モーダルの focus trap を維持する。

## 検証表

| 対象           | 必須証拠・受け入れ条件                                                                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全体の情報構成 | 320 / 390 / 1024 / 1440px × light/dark × exact before/after の全 App 描画。ナビ→一覧→本文、モバイル戻る/進むで状態維持                                                                  |
| 一覧の現在位置 | すべて・特別一覧・フィード・グループ・タグ・コレクションと0件の見出しをテスト                                                                                                           |
| 最小一覧幅     | 200px × light/dark × fine/coarse pointerで6表示操作の領域・高さを実測し、focusとSpaceで到達できることを確認                                                                             |
| 常用操作       | 5表示・未読/保存・カテゴリ/日付などの絞り込み・クリア・検索空状態を実ブラウザーで操作                                                                                                   |
| 読み方         | 共通入口から見た目を変更し、記事選択を保持。ドパガキモードを起動/終了し可視入口へ focus。既存の推薦スコープ・キュー・動画検証を再実行                                                   |
| 設定とNSFW     | 常用サイドバーの大きい解除行がない。設定で現在状態確認・解除、オフライン・reload・長押し・既存有効化条件の回帰テスト                                                                    |
| キーボード     | 実際のグローバル/記事フックを同時 mount。button・子要素・summary・custom control のSpace、body/Shift+Space、trusted focus reader をテスト。実ブラウザーでも mounted reader の背後で操作 |
| 視認性・サイズ | 新しい文字付き操作の computed contrast ≥4.5。読書設定と隣のAI操作の実測高さが一致。coarse pointer 操作44px以上                                                                          |
| 品質           | final head の lint/fmt・typecheck・全 unit・offline contract・production build・既存 Chromium と独立レビュー                                                                            |

画面の実寸・画像・操作結果はCI artifactの exact SHA とフォント来歴に結び付ける。合成fixtureはproduction App/CSSを使うが、Nextの実サーバールーティング、実アカウントの同期、実機screen readerの検証ではない。未検証項目を完了扱いにしない。

## 監査で残った事項

- 高: toolbar の意味がアイコンだけでは読めない箇所。今回、短い主要ラベル・四角い共通形・読み方入口で改善する。
- 高: Space がコントロール操作を奪い、本文を二重スクロールする。master実フックで再現して修正する。
- 中: タイトル下の3行予約領域は短いタイトルでも余白が残る。既存のリサイズ時安定性とline-clamp契約があるので、今回の操作整理と混ぜず、実寸を比較して次の判断をする。
- 中: 長いライブラリ・最小幅のサイドバー、200%文字拡大、設定内検索、未読・通信エラー状態は継続して実描画を監査する。今回見えていない状態まで改善済みと宣言しない。

## 展開・復元

#1469 の現在の情報密度を維持する差分のみ。API・認証・通知権限・課金・データ形式を変更しない。通常のレビュー/CI条件がそろってからマージし、master CIと影響動作を確認する。UI commitの通常revertで戻せる。Serena撤廃とCodex/README/roles整備は別PR。
